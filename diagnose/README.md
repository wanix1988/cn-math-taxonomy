# 数学知识点诊断小工具

纯静态、可离线的网页小工具：学生或家长选一个目标知识点（或整章），工具沿先修关系自适应出题，找出**薄弱的根因**，给出**按先修顺序排列的学习路径**，并列出相关的课标条目。无构建步骤、无外部 CDN、无后端；进度只存在浏览器的 localStorage 里。

> 数据（知识点、先修边、课标映射）都是 AI 生成的初稿，未经教师审核，诊断结论仅供参考。

## 运行

在项目根目录（不是 `diagnose/` 里）：

```bash
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/diagnose/
```

页面用 `fetch('../data/*.json')` 读数据（含 `questions.json` 题库；缺失时自动回退到 `topics.json` 里每个知识点的 `diagnostic_question`），不能直接用 `file://` 打开。全站顶部导航都能进来：首页是根目录的 `index.html`，知识图谱在 `../explore/`。样式与首页、图谱共用 `../assets/site.css`，本目录的 `style.css` 只写诊断页自己的布局。

### URL 参数（演示 / 截图 / 分享入口）

| 参数 | 含义 |
|---|---|
| `target=cnm_221` | 直接以某个知识点为目标（可用逗号写多个 id）。没有 `demo` 时，若本机已有同一目标的存档就继续，否则开始新诊断 |
| `chapter=七上 第一章` | 以整章为目标（写法同列表里的“册 + 章号”，URL 里记得编码空格） |
| `grade=七年级` | 按年级整体诊断（筛查模式）：一年级 … 九年级，等于该年级上、下两册；也可写 `七`。与 `target` / `chapter` 同时出现时以 `target` / `chapter` 为准 |
| `volume=七上` | 只诊断一册（`七上`、`八下` 等）；可单独使用，也可和 `grade` 一起用（须是同一年级，否则报错；`grade=七年级&volume=上` 也行） |
| `demo=1` | 演示模式：由程序模拟一位学生作答并直接到结果页，**不读写存档**。模拟规则：目标两题都错（薄弱）；它的第一个可测先修也两题都错（薄弱，根因）；再往前一个知识点（没有就取目标的另一个先修）先错后对（不稳）；其余按当前 confirm 连续答对（掌握）——所以结果页能同时看到 掌握 / 不稳 / 薄弱。对 `grade` / `volume` 的筛查会话，模拟学生按知识点序号：约 1/6 不会、1/6 不稳（第一题错、第二题对）、其余都会，结果页有按章汇总 |
| `step=2` | 与 `demo=1` 合用：只自动答前 2 题，停在第 3 题的出题页 |
| `limit=16` | 本次诊断的题量上限（**按题计**，不写则用设置里的值：单点 / 整章默认 16，可调 8–30；整体诊断默认 40，可调 20–60） |
| `seed=abc` | 固定选题的随机种子：同一目标、同一种子、同样的作答，出的题完全一样（测试、复现用）。不写则每次随机；演示模式默认种子 `demo` |

例：`http://localhost:8000/diagnose/?target=cnm_221&demo=1`、`http://localhost:8000/diagnose/?grade=七年级&demo=1`、`?volume=七上&limit=50`

## 使用流程

1. **开始页**：先选学段（全部 / 小学 / 初中 / 高中），再用搜索找知识点。册、章列表仍在，默认折叠，需要时再展开；点「选为目标」，或点章标题旁的「以整章为目标」。题量上限可在 8–30 之间调（保存在本机）。手机上选项按钮不小于 44px。
   **按年级整体诊断**：开始页的第二张卡片。选一～九年级，或高一、高二、选必一、选必二、选必三。小学和初中再选「整年级 / 上册 / 下册」；高中不拆上下册，必修两册的范围按钮是「必修整册」，选择性必修三册是「整册」。卡片上会显示范围内的知识点数；题量上限可在 20–60 之间调（默认 40，保存在本机，和单点的上限分开）。本测评检查本年级知识点是否掌握，不是竞赛拔高：按「基础 / 提高 / 拓展」出题，先提高再拓展确认，答错先补基础。点「开始整体诊断」后用筛查模式出题：诊断范围就是所选年级 / 册的知识点。连续答对后，只连带跳过范围内沿硬先修能到达的点；软边多半是教材先后顺序，不会因为答对链尾的一篇就跳过前面整册。确认后仍错才在范围内回溯先修（硬先修在前），范围外的先修会标为「前置知识」并提示未检查。存档会记下模式，刷新后「继续」仍是整体诊断。URL：`grade=高一`、`grade=高二`、`grade=选必二`（也接受 `高一必修`、`选择性必修第二册`）。英语在三年级到九年级之外，还有必修一、必修二、必修三、选必一到选必四，URL 必须带 `subject=english`（例如 `grade=选必一`、`grade=必修一`，也接受 `选择性必修第一册`）。英语高中不拆上下册：必修三册的范围按钮是「必修整册」，选择性必修是「整册」。不带 `subject` 时这些写法不会选到数学。
2. **出题页**：每题显示知识点、难度（基础 / 提高 / 拓展）、题型、这是本知识点的第几题，以及“为什么现在问这个”（目标本身 / 因为某点两题都没通过而回溯 / 第一题没过的复测）。回溯到更低年级时会标「前置知识」。
   - 选择题：点选项再「提交答案」；数值 / 短答题：输入答案后「提交答案」（回车也行）；开放题：可写思路，再「看参考答案并自评」；
   - 「看参考答案并自评」→ 自己点 对 / 不对 / 不会；
   - 「不会」→ 先显示参考答案和解析，再点「下一题」，记为没答对。
   **每题作答后都会显示参考答案和解析**（自动判题时也显示），然后点「下一题」。自动判定后可点「判错了，…」手动改判。还有「撤销上一题」「重新开始」。
3. **结果页**：薄弱根因、**不稳的知识点**、推荐学习路径（文字列表）、路径图（Cytoscape + dagre，风格与知识图谱一致：小学 / 初中 / 高中分色，硬先修实线，软先修虚线，薄弱根因高亮；长名称省略，悬停或点按看全名）、已掌握 / 未测列表、相关课标条目汇总、答题记录（含题目、你的答案、参考答案，可逐题更正，更正后整份诊断重新计算）。整体诊断的结果页在顶部统计之后多一个**按章汇总**：每章的 掌握 / 不稳 / 薄弱 / 未测 数量（含色条）和薄弱、不稳的知识点名称，薄弱的章排前面；如果有薄弱点的先修在所选范围之外，会提示“部分薄弱点的先修在所选范围之外，未检查，可对其做单独诊断”，并在对应的根因下写出是哪些先修。整体诊断里不标「目标」，课标汇总只含学习路径上的点。可「导出 JSON」（含每道题的 id、你的答案、结果、参考答案、解析），或「打印 / 另存为 PDF」（有 `@media print` 样式，打印时自动展开所有折叠项）。也可以「生成分享图」：用 canvas 画一张 1080×1920 的竖图（站名、学科和范围、已掌握 / 不稳 / 薄弱 / 未测、最薄弱的 2–3 章或知识点、1–2 个根因、日期），底部二维码指向 `https://math.pansgo.com/?from=share`，旁边是「扫码打开本站」。图上没有姓名，也不写付费。桌面端在弹层里下载，窄屏用图片本身提示长按保存。二维码由 `assets/vendor/qrcode.js`（qrcode-generator 2.0.4，MIT）在本地绘制。
4. 刷新页面不会丢进度；开始页会提示“继续 / 放弃存档”。出过的题 id 另存在 localStorage（`cnmDiagnose.seen.v1`），下次诊断优先出没出过的题。

## 算法

全部在 `engine.js`（UMD：浏览器里是 `window.DiagEngine`，Node 里 `require` 即可；纯函数、无 DOM，会话对象可 JSON 序列化）。UI 只负责调用和渲染。

**图与子图**：`dependencies.json` 里 `topicId` 以 `prerequisiteId` 为先修。目标集合的先修子图 = 目标 + 所有祖先（小学正式知识点和初中知识点都在同一张图里），并做稳定的拓扑排序（先修在前，同层按 `topics.json` 的顺序，保证结果可复现）。每个节点的先修按 **hard 在前、soft 在后** 排序。开始页可以用「全部学段 / 小学 / 初中 / 高中」筛选。URL 里的旧编号 `cnm_ext_*` 会按 `data/id-aliases.json` 展开成对应的小学知识点再诊断（例如 `?target=cnm_ext_002`）。

**自适应出题**（`createSession` / `nextQuestion` / `nextItem` / `applyAnswer`）维护一个出题栈。**每个知识点需连续答对 `confirm` 题才判掌握**（默认 **3**，开始页可选 2 / 3 / 5，保存在本机；题库更少时以题库为准）：

- 初始栈 = 目标按“离目标最近”（拓扑序靠后）排序；所以**先问目标本身**，整章作为目标时先问章末最靠后的点。
- **连续答对满额** → 该点记为**掌握**。单点 / 整章诊断把它的**所有祖先**（含小学节点、含软边）记为“掌握（推断）”，不再问。整体筛查只沿**硬先修**推断：软边通常只表示教材顺序（语文按课文前后相接就是这种边），答对后面的课文不能据此跳过前面的课文，否则整年级会被收成两三道题。
- **中途答错或「不会」** → 还没有结论，**同一知识点再出一道确认题**（同级或更容易，见下「选题」）：
  - **确认题也错 / 不会** → **薄弱**（weak）：把它还没判定的直接先修（hard 先、soft 后）压到栈顶，**深度优先**继续往回走。**只有这种情况才向先修回溯。**
  - **确认题答对** → **不稳**（shaky）：结果页单独标出，并**放进学习路径作为需要补的点**；但**不**向它的先修回溯（默认如此：一次对一次错更可能是粗心或不牢，不足以推断先修有问题；它的先修保持「未测」，除非别处的回溯、或后续目标的答对把它们判定了）。
- 如果一个知识点题库不够（或确认题已无可出的题），答错就直接判薄弱；题库少于 `confirm` 时，答对全部可出题即掌握。
- 已判定（掌握 / 不稳 / 薄弱）的点不会重复问；直接作答的判定不会被“推断掌握”覆盖。
- 小学知识点与初中知识点一样出题。图里已经没有不出题的 `cnm_ext_*` 节点。
- 题量上限按**题**计（不是按知识点），默认 **16**，可调 8–30（结果页还可以「再多答 4 题」）。到上限时剩下没测的点标为「未测」；如果某个知识点只答了第一题（答错）就到上限，没来得及复测，会暂按薄弱处理并在结果页提示「未复测」。

**选题**（`pickQuestion`，纯函数，由会话里的 `seed` 决定）：

- 用 mulberry32 伪随机数，随机数只取决于 `(seed, 知识点, 第几题)`，所以**同一种子、同样的作答 → 出题完全相同**，`replay`（刷新恢复、撤销、更正）也因此一致。URL 参数 `seed=` 可固定种子；不写则每次会话随机生成并存进存档。
- **第一题**：优先 **standard（提高）**；没有提高题再退到 basic；尽量不出拓展。优先**没出过**的（已出过的题 id 记在 localStorage，创建会话时作为 `avoid` 传给引擎；全都出过就允许重复）。
- **连续答对**：优先出 **challenge（拓展）** 确认掌握，再提高，再基础。
- **答错后的确认题**：**同级或更容易，优先 basic**，其次与第一题同难度，再其次其它更容易的，最后（没有别的选择时）才出更难的；难度优先于「没出过」，同一难度档里仍优先没出过的。
- 本次会话里同一道题不会出第二次。

**结果**（`summarize`）：

- **根因** = 判为薄弱、且它的直接先修里**没有**薄弱点的节点（先修里是「不稳」的不算薄弱）。若它的先修里还有题量用完没测到的点，会标出“真正的根因可能更靠前”。手造图里如果还有没有诊断题的节点，结果里会单独标出这些先修；现行数据里小学知识点都有题。
- **不稳** = 中途答错过、确认题答对的点（`summary.shaky`）。
- **学习路径** = 从所有根因**和不稳的点**出发、沿“被依赖”方向可达的、在先修子图内的节点，去掉已掌握的，**按年级从低到高排列**（同一年级里保持拓扑序，先修在前）。薄弱点和不稳的点一定都在路径上；路径里的「未测」点建议先自查。答错初中题会一路问到小学。
- **路径图**（`layout` 选出节点和边，页面用 Cytoscape + dagre 排版）：画“路径 ∪ 目标 ∪ 根因 ∪ 实际问过的点”。边取这些点上可达关系的传递约简；直接的硬先修画实线，软先修画虚线，中间省略了未画出的点时画点线。先修在上、目标在下。文字列表仍是完整的学习顺序。

**一致性**：`replay(graph, targets, answers)` 由作答记录重建会话。刷新恢复、撤销、更正某题都是“改记录再重放”，所以不会出现状态与记录不一致。

## 判题规则

按题型判（`judgeQuestion(question, userText)`），只在**可靠**时给出对 / 错，其余让用户对照参考答案自评（返回 `correct` / `wrong` / `manual`）：

- **choice**：直接比字母（`B`、`b`、`(B)`、`B.` 都行），也接受输入选项文字（规范化后相同）；是别的选项就判错；认不出来交给自评。界面里选择题是点选项。
- **numeric**：用下面的数值规则；`answer` 里有多个答案时，带 `unordered: true` 才顺序无关，否则**按顺序**逐项比较；`accept` 里的等价写法也算对。
- **short**：规范化后与 `answer` 或 `accept` 精确匹配才判对；不匹配**不判错**，交给自评（文字、代数式写法太多）。
- **self**：一律自评。
- 回退模式（没有题库，题是 `diagnostic_question`）：按下面的通用规则。

下面是数值 / 文本的通用规则（`judgeAnswer`）：

规范化（两边都做）：全角转半角（NFKC：`１/２`→`1/2`，`，；：（）－` 等）、去所有空白、统一中文标点（`、`→`,`，`。`→`.`，`×÷`→`*/`）、`²`→`^2`、`90 度`/`90 °`/`90度角`→`90°`、`≦≧`→`≤≥`、去掉结尾句号和“答：”前缀、千分位 `1,000`→`1000`、带分数 `1 1/2` / `1又1/2`。

比较规则：

1. 规范化后文本完全相同 → 对。
2. 拆成多个答案（按 `, ; 、 ，` 以及“和 / 或 / 与 / 及”拆，括号里的逗号不拆，所以坐标 `(1,2)` 是一个答案），**顺序无关**地比较：`-3 和 -1/2` ≡ `-1/2，-3`。
3. 每个答案若能安全解析为数值，就用**精确有理数**比较（整数、小数、分数、百分数、带分数、带正负号或括号）：`1/2` ≡ `0.5` ≡ `2/4` ≡ `50%`；`1/3` ≢ `0.333`。坐标 `(a,b)` 逐项比较。
4. 变量名：只有一个答案时 `x=3` ≡ `3`；多个答案且参考答案带不同变量名时（`x=3，y=2`），写了变量名就按变量比较，没写就按参考答案的出现顺序比较，所以 `x=2，y=3` 判错。
5. 单位：别名等价（`米`=`m`，`平方米`=`m²`，`度`=`°`…）；一边没写单位放行；两边是不同的已知单位判错；不认识的单位交给自评。
6. 双方都是数值但不等价 → 错；**代数式、文字、其它写法** → 只在规范化后完全相同时判对，否则**不下结论**，显示参考答案让用户自评（例如 `y=3x+2` vs `y=2x+3` 也交给人，因为 `y=(x-2)²-1` 与 `y=x²-4x+3` 这类等价写法无法可靠判断）。

界面上始终提示：自动判题是近似的，以参考答案为准，可以手动更正。

性质测试里，“一致的学生”指已掌握集合对祖先封闭；题量不限时，诊断出的薄弱集合应恰好等于该学生不会的点，根因应恰好是“自己不会、先修都会”的点。

## 导出 JSON 的结构

`version: 2`、`mode`（`target` 或 `screen`）、`label`、`targets`、`limit`、`seed`、`asked`、`finished`、`limitReached`、`answers`（每题：`order`、`topicId`、`questionId`、`difficulty`、`type`、`prompt`、`userAnswer`、`result`、`referenceAnswer`、`explanation`）、`weakRoots`（含掌握标准、课标 id、未测先修、范围外先修 `outOfScopePrereqs`）、`path`（带序号、状态）、`weak`、`shaky`、`chapters`（仅整体诊断：每章的 `label`、各状态数量，以及 `weakTopics` / `shakyTopics` / `untestedTopics`）、`mastered`（直接 / 推断）、`untested`、`standards`（id + 原文）。


## 盲区再测

结果页会把本轮薄弱 / 不稳写入本机盲区账本（`cnmBlind.local.v1`，由 `assets/blindspots.js` 维护），并提供「再测薄弱根因 / 薄弱点 / 不稳点」入口；开始页若已有盲区会列出最近几条。整体筛查的按章汇总里，薄弱 / 不稳章可「再测本章」。全部汇总见 `children/history.html`。不上传答题内容；演示模式（`demo=1`）不写入。

## 局限

- **每知识点确认题数默认为 3**（可选 2 / 3 / 5）：题库每个知识点 4–5 题。选择题仍有蒙对概率，「不稳」只是提示，结果是“线索”不是“结论”。重测多次会遇到重复的题。
- **不稳不回溯**是一个设计取舍：中途答错但确认题对时不继续追查先修，可能漏掉真正的薄弱先修；它们会在路径里标出，建议自查。
- 答对一个点就推断它的所有祖先已掌握，依赖先修图的准确性；先修边是 AI 生成、未经教师审核的初稿。
- 小学、初中、高中必修和选择性必修在同一张图上。题量上限默认 16，一次诊断往往问不到一条很长的先修链的最前面；把上限调大，或对结果里的「未测」点再诊断一次，才能走到一年级。旧链接 `cnm_ext_*` 只跳到别名文件里的代表知识点，不是该主题的全部小学知识点。选择性必修的 `grade` 12–14 只用来分册，不是教学年份。英语高中的 `grade` 10–16 同样只分册（必修三册、选择性必修四册），页面不写成高一到高四。
- 判题只覆盖数值、分数、坐标、多答案和带单位的简单答案；代数式、文字题、证明题一律自评。`2/4` 这类未约分的写法也会被判对（只比数值）。
- 薄弱点只由“答错 / 不会”决定，不区分概念性错误和计算失误。
- 路径图由 dagre 排版。跨很多层时边可能从别的节点旁边穿过；名称在图上会省略，完整顺序以文字列表为准。
- 进度只存在当前浏览器的 localStorage，换浏览器或清除数据就没了；隐私模式下可能无法保存。
- 手机上可以使用：开始页以搜索为主，选项和主要按钮不小于 44px，窄屏不会横向撑出页面。无障碍（键盘 / 读屏）只做了基本的语义标签。

## 试卷质量分析与 Agent 交接协议

`papers.html` 的离线算法（`assets/paper-quality.js`）只做**通用几何**：红笔连通块、分栏、题目带、印刷题号、旋转方向、去重，以及基于录入字段的统计与综评。它不再为任何一份具体试卷保存笔迹模板、固定题号、答案或写死的讲评文字。

读懂题目文字、手写订正、知识点归因和针对性讲评需要语义理解，因此交给 Agent，有两条通道：

1. **主链路（默认）**：导入页的「Agent 分析试卷」卡片里复制提示词或下载请求包 → 把照片一并交给 Agent（例如 WorkBuddy）→ 把 Agent 回复直接粘进「粘贴结果并导入」，或保存成 `.json` 用「导入 Agent 结果」导入。请求包默认**不含照片**；勾选「请求包附带照片」才把图片转成 data URL 写进包里。
2. **可选直连**：在「模型设置」里填一个兼容 OpenAI `chat/completions` 的视觉模型服务（地址、模型名、可选密钥），打开开关后点「用模型直接分析」。开关默认关闭，且每次发送前都会再次确认；配置只存在本机 `cnmPaperAgent.v1`。

### 请求包（导出给 Agent）

`PQ.buildAgentRequest()` 生成：

```
schemaVersion, kind: "paper-analysis-request", createdAt,
paper: { title, grade, subject, examDate, score, total, deduction, headerHint },
pages: [{ index, id, width, height, imageName, image: dataURL|null,
          candidates: [{ number, kind, prompt, numberConfident, box: {x,y,w,h} }] }],
catalog: { subjects, reasons, knowledgeHints },   // knowledgeHints 来自本地 topics.json
outputSchema, instructions                        // instructions 是完整提示词
```

`box` 是相对**整张照片**宽高的 0～1 归一化坐标，候选框和题号都可能不准，以照片为准。`headerHint` 是离线在卷头读到的大号数字，可能是得分也可能是扣分，只作线索。

`instructions` 本身自带候选框清单、坐标说明和「照片必须随请求提供」的约束，可以脱离请求包单独复制给 Agent。一张照片可能拍到跨页的两页试卷，`pages[].index` 与**照片序号**一致，Agent 应按照片分组返回 `items`，不要按印刷页码另拆页；同一大题的不同小题允许重复题号分别列出。

### 结果 JSON（Agent 导入）

只输出一个 JSON 对象，不要 Markdown 代码块之外的解释文字：

```json
{
  "schemaVersion": 1,
  "kind": "paper-analysis-result",
  "paper": {
    "title": "七年级期中数学", "grade": "七上", "subject": "math",
    "score": 88, "total": 100, "deduction": 12,
    "summary": "综评正文，2～5 段，用换行分隔。",
    "suggestions": ["先补一次函数", "再做两道变式"]
  },
  "pages": [{
    "index": 0,
    "items": [{
      "number": "12", "prompt": "题目原文", "studentAnswer": "B",
      "rightAnswer": "C", "knowledge": "一次函数", "reason": "概念不清",
      "reasonNote": "把 k 当成截距", "kind": "圈出",
      "x": 0.12, "y": 0.24, "w": 0.3, "h": 0.08, "confidence": 0.9
    }]
  }]
}
```

`reason` 必须是 `概念不清 / 计算失误 / 审题不清 / 步骤不完整 / 记忆不牢 / 时间不够 / 其他` 之一或留空；`correction` 等价于 `rightAnswer`；`match` 可写 `number` / `box` / `new`。读不清的字段留空，不要编造。

### 合并规则

`PQ.applyAgentResult()` 的对齐顺序：

1. 先按**框重叠**（IoU ≥ 0.4）匹配；离线偶尔会把一条红线画成巨大的框，面积超过 Agent 框 4 倍的候选不参与匹配，避免小题被吞掉。
2. 再按**同页题号**匹配，但题号相同而位置相差太远时不合并（离线题号常认错），改为新建。Agent 没给 box 时仍按题号合并；显式 `match:"number"` 可强制按题号合并，`match:"new"` 强制新建，`match:"box"` 只按框对齐。
3. 都匹配不上就新建错题，用 Agent 给的 box；合并进离线候选时也会把框换成 Agent 的位置。`match:"new"` 只表示**不与离线候选合并**，重复导入同一份结果时，同页同题号同题目的 Agent 条目仍会复用，不会每次多出一批。
4. 导入结束后**清掉没被 Agent 认领的「自动标出」占位候选**（人工补过知识点、答案或错因的保留），避免错误题号混进错题清单；`{ keepOffline: true }` 可关闭这个清理。

默认只填空字段，不覆盖人工已录入的内容（离线占位文本「自动标出：…」和跟着算出来的题号视为空）；勾选「导入时覆盖已经填好的内容」才强制覆盖。草稿里预填的满分 100、年级（来自孩子档案）、学科（来自网址默认值）都不是人工录入，Agent 读到别的卷面信息时可以改正；用户真正动过这些字段后（`*_Edited`）就不再覆盖。重复导入同一结果不会新增错题。Agent 结果里的 `paper.summary` 会写入草稿的 `agentSummary`，综评优先采用它并标注来源，可点「清除 Agent 综评」回到本机生成；这些字段会随试卷一起存进本机数据库。

### 实测记录

用一份五年级上册阶段巩固卷（4 页、2 张横拍跨页照片，得分 83）做过端到端验证：离线几何只在每张照片上标出 3 个红笔区域且题号多数不准，属于**候选层**的已知边界；Agent 按提示词读照片给出 10 道错题后，合并结果为 10 条、题号与框全部来自 Agent，4 个误判占位候选被清掉，重复导入幂等，综评采用 Agent 文本。结论：**离线只宜做粗定位，语义与最终错题清单以 Agent 为准**；页面里的「重新自动分析」提示语也据此改成仅供参考。

相关测试：`node tests/test_paper_quality.js`（含协议、页面渲染、真实卷暴露的空间误合并与占位清理用例、直连模块的模拟请求）。

## 书写质量：硬笔楷书评价量表

`writing.html` 的**中文**部分按 `assets/handwriting.js` 里的 `RUBRIC`（`hardpen-kaishu-rubric-v1`）逐字评判；**英文**部分按 `RUBRIC_EN`（`hengshui-print-hand-rubric-v1`，衡水体）逐字母评判，两者共用同一套逐字评判与页面组件。中英混排仍用原来的六维概览。照片只在浏览器内存里分析，不上传、不入库。

### 依据

- 教育部教育考试院《书画等级考试（硬笔书法）考试大纲》：初级 1—3 级**书写卷**按「笔画 / 结构 / 章法」= **30 / 50 / 20** 计分，要求笔画形态基本正确、结构平正匀称比例适当重心稳定、通篇大小匀称字在格内基本居中、书写整洁无涂改乱画。[大纲 PDF](https://cjcx.neea.edu.cn/res/Home/2312/0e969438bbbe0b2163371a87c2fbcf01.pdf)
- 《义务教育语文课程标准（2022 年版）》：第二学段「规范、端正、整洁」，第三学段「行款整齐，力求美观」。
- 《中小学书法教育指导纲要》（教基二〔2013〕1 号）：基本笔画、笔顺规则、间架结构（左窄右宽、包围结构等）、行款布局。

### 逐字评判

`HW.assess()` 中文返回 `characters` 数组，**每个字一条**：`line / column / box`（归一化，可与圈注 `charIndex` 对应）、`score / grade / level`、`scores`（笔法 / 结体 / 章法分项）、`verdict`（含量化偏差的完整评判）、`advice`（保持意见或优化建议）、`findings`（命中条款，每条给判据、偏差数值、改法 `action`、练法 `train`）、`passedCount / itemCount`。页面「逐字评判」可按等级筛选、展开命中条款、点「在图上定位」高亮该字；下载的标注图不带定位框。

等级为优秀 ≥90 / 良好 ≥80 / 合格 ≥65 / 待改进 <65。**单条明显失度会封顶**：字级最差条款 <62 分最高只能「待改进」，<78 分最高「合格」，其余有问题最高「良好」，避免加权平均把「一个字写得很扁」稀释成优秀却挂着红圈；维度内部同样按最差条款 `+8` 收敛，避免整行挤成一团却被平均成章法满分。行款类条款（L1—L4）按所在行评定、计入章法分，但**不生成逐字圈注**，行级问题仍由原来的行标注提示。

口径说明：**单字分**只按笔法与结体（30:50）计算，**章法是整行的属性**，按行另评但写进该字的评判与建议里；页面「评价」的总分按量表三维度 30/50/20 加权（含按行评定的章法），`charAverage` 是单字分均值。因此可能出现「每个字都写得好、全页因字距过挤只评比较工整」，这是有意的：不因为一行排得挤就把每个字判成不及格。

### 边界

本工具**不识别写的是哪个汉字**，因此以下项目不评判、也不猜测：`unmeasurable` 列出的字形正误与错漏字、笔顺与起收笔动作、部件搭配与避让穿插、撇捺出锋等笔画形态、坐姿执笔与书写速度。这些需要教师或能读字的视觉模型复核。分数用于定位练字重点，**不等同于考级成绩**。

相关测试：`node tests/test_handwriting.js`（46 个用例，含两套量表的权重与不可篡改性、逐字／逐字母字段完整性、失度封顶、行级章法评定、英文量表与页面渲染、四线格 / 田字格版式、印刷标题跳过、视觉行还原与短行／下伸字母判据、行级提醒分栏、无浏览器页面渲染验证）。

## 书写质量：衡水体英文评价量表

### 依据与性质

**衡水体不是国家或行业统一标准**，而是源于河北衡水中学教学实践、被中小学英语字帖与中高考备考资料广泛采用的「手写印刷体」规范。本量表把它整理成可测量的判据，并对照《义务教育英语课程标准（2022 年版）》对字母书写、大小写、标点、词距的要求，以及书面表达「卷面整洁、书写工整」的要求：

- 《义务教育英语课程标准（2022 年版）》：字母书写规范、大小写与标点正确、词间留空格、行款规范。
- [衡水体书写十要素](https://www.sohu.com/a/279175871_616026)：字形、笔顺、格位、宽度、高宽对应、斜度（与线夹角 75—85°，即右倾约 5—10°）、不连写、字距约 1mm、词距约 3mm、行距均等；字母底部贴线、顶部留白约 3/5。
- [中考英语书写规范要求](https://www.jinbojiaoyu.com/news/34394)：大写占上中两格，小写按中格／上伸／下伸分组；全篇斜度一致；词内字母紧凑、词间约一个小写 o 宽；标点规范、卷面整洁。
- 华夏万卷《初中英语同步字帖·衡水体》：圆润饱满、竖笔直、起收笔不带钩、高宽与间距统一、字母间无连笔不交叉。

`HW.getRubric('en')` 返回该量表深拷贝；不带参数返回中文量表。

### 12 项可测量条款

| 维度 | 条款 | 分值 | 判据 |
|---|---|---|---|
| 笔画·线条 30 | E1 线条清晰 | 8 | 墨色不过淡、笔画完整 |
| | E2 用力匀净 | 6 | 同页墨色一致 |
| | E3 笔画洁净 | 6 | 无涂黑墨块 |
| | E4 不连笔不交叉 | 10 | 字母独立、相邻不粘连；连写并成的宽字形会被标出 |
| 字母·规格 40 | E5 大小同高 | 12 | 按高度分「矮字母／大写与上伸字母」两组，组内同高 |
| | E6 底部贴线 | 12 | 底部落在同一基线 |
| | E7 斜度统一 | 10 | 全篇角度一致、不过斜；5—10° 右倾是标准，工具不量绝对角度 |
| | E8 宽窄匀称 | 6 | 宽高比与同页字母接近 |

### 逐字母评判与口径

与中文完全同一套机制：`characters[]` **每个字母一条**，含 `line / column / box`、`score / grade / level`、三维分、含量化偏差的 `verdict`、优化建议 `advice`、命中条款 `findings`（判据＋偏差数值＋改法＋练法）、`passedCount / itemCount`；写得好的字母也给出保持意见与进阶建议。等级为优秀 ≥90 / 良好 ≥80 / 合格 ≥65 / 待改进 <65；单条明显失度封顶，维度内按最差条款 `+8` 收敛。

**字母分只计笔画与字母规格（30:40），章法按行另评并写进该字母评判**；字距、词距、行距、行首等行级条款对本行每个字母生效（不挂在词尾那一个字母上被平均稀释），但**不生成逐字母红圈**。页面「逐字母评判」可按等级筛选、展开命中条款、点「在图上定位」对照圈注。

**避免大小写误判**：衡水体里大写与上伸字母本来比矮字母高约 1.5 倍，评判先按高度分成两组再比较组内同高，不会把合法的高度差判成「大小不匀」。

### 边界

本工具**不识别写的是哪个字母**、也不量绝对倾斜角度，因此 `unmeasurable` 列出的项目一律不猜：字母字形正误与拼写、大小写使用规则、圆润饱满与起收笔是否带钩、四线三格具体占格、标点种类与标点后空格、笔顺运笔、单词移行与段首缩进、坐姿执笔与书写速度。这些需要教师或能读字的视觉模型复核；分数用于定位练字重点，**不等同于考试卷面分**。

## 书写质量：格线、印刷标题与语种自动识别

### 问题

四线格英语作业纸（顶部常带彩色印刷中文标题，如「英语作业纸」）原先会被判成中文 / 中英混排，且只对顶部几个印刷汉字圈注，正文一行都看不到。根因不是语种规则本身：格线进入笔迹掩膜后，和整行字母粘成一条 430×28 的超长连通块，`isRuling` 把整行当成格线丢弃；最后只剩印刷标题附近的碎块，字数少、方块特征强，自然被判成中文。

### 处理链路（`assets/handwriting.js`）

1. `removeRulingLines(mask, w, h)`：按行 / 列投影找出几乎整行都是线的格线行，整行（整列）从掩膜里剔除，返回 `hLines / vLines / hEven / vEven / removed`。清横线后重算列投影，避免把横线的累计误判成竖线。
2. `mergeCutGlyphs(raw)`：格线抠掉后，跨线的字母（`l`、`g`、`d` 一类）会被切成上下两块；把 x 高度重叠、垂直只差几像素的碎片按面积加权拼回一个字。
3. `skipPrintedHeaders(lines, H)`：连通域带 `chr`（平均色度）。印刷标题常用彩色油墨、正文手写多为中性黑灰；只在页面最上方两行、字数不多、且该行彩色字占比高、全页仍有足量中性墨字时才剔除，避免误删整页蓝钢笔字。返回跳过字数。
4. `detectScript(lines, ruling)`：不再只按行数投票。按**非标点字数量**投票，叠加全页宽高比中位数、有词间空隙的行数、以及格线版式证据（横线成排且竖线很少 → 四线格 / 横线纸；横竖都成格 → 中文方格纸）加权，返回 `{ script, evidence }`。报告新增 `detectedScript / scriptEvidence / skippedPrinted / ruling`，页面显示识别依据，判错可手动切「中文 / 英文」。
5. 切字路径双向兜底：连通块比按行切出的字多太多（一字拆散）或少太多（多字粘连 / 被格线吃掉）时，都改用按行带 + 列投影切出的字。

### 边界

- 仍有 1 行英文（`When I close my eyes at night.`）因笔迹与格线几乎完全重叠、抠线后剩余墨迹不足而漏评。这是离线几何分析的固有限制；页面提示可把该行裁出来单独上传。
- 语种判定是**版式与几何证据加权，不是 OCR**。中文横线信纸、整页彩色墨水书写、印刷字与手写同色等边缘情况仍可能误判，所以依据会明写在报告里，并保留手动切换。
- 印刷标题排除只看墨色差异与位置，不读字内容；彩色印刷与彩色手写混排时可能误跳整行。
- 格线剔除会轻微改变笔画密度类判据（字母被线切过再拼回），分数用于定位练字重点，不作绝对评价。

## 书写质量：行级判据修正（2026-11-08 第二轮）

真实四线格照片出分后发现：章法维度被三类几何噪声压低，且改进建议里混进了优秀字母的表扬。这一轮只改判据与呈现，不改动识别链路。

### 1. 行首（E12 / L3）：短行不比，异常值不写进文案

原判据把每一行的 `x0` 都与「全页行首中位数」比较。四线格作业纸上有居中标题、右上角日期、只有两三个字母的残行，于是出现 `本行行首比全页错开 1833% 字高` 这类物理上不可能的数值，11 行全部命中 `E12`。

新增 `visualRows(lines, em)`：按每行非标点字数算出「正文行」阈值 `max(4, 中位字数 × 0.55)`，行首中位数只由正文行决定；只有正文行才判行首，偏差超过 2.5 字高直接视为非正文版式、不写进文案。中文 `L3` 用同一尺度。真实照片上 `E12` 从 11 行降到 5 行（3 行行首、2 行长笔越行），最大偏差从 1833% 降到 200%；中文 `L3` 从 1 行降到 0 行。

### 2. 行距（E11 / L2）：先还原视觉行，再算行距

原判据用相邻 `lines[i].cy - lines[i-1].cy`。格线把一行字母切成上下两条「半行」时，半行中心距被当成行距，报出 `行距只有 0.90 倍字高，行与行太挤`，而照片上诗句实际隔行书写、行距充足。

`visualRows` 把中心距小于 1.15 字高的相邻行并回同一视觉行，`pitchOf(row)` 返回该视觉行与上一个视觉行的中心距。真实照片上 `E11` 从 5 行「太挤」降到 2 行，且原因变成**真实的整行基线漂移**（`整行基线越写越往上`）；合成样本中真正密排的行（1.25 倍字高）仍照常报出，没有被合并吞掉。

### 3. 基线（E6）：下伸字母分组，不一刀切

原判据用整行 `bottom` 中位数当基线，于是合规的 `g / j / p / q / y` 下伸被当成「没贴线」。现在基线只由不下伸的字母决定；高度超过矮字母组 1.2 倍且字心明显偏下的字形识别为下伸，其 `bottom` 先扣掉下伸量再比较。真实照片上 `E6` 命中 35 → 28，字母规格维度 91 → 93。

### 4. 建议分栏：行级提醒不再冒充逐字母改进

`groupNotes` 会把「写得规范（有 55 处）」这类表扬也聚成一条建议，且 detail 里拼着行级章法，容易被误读成「55 个字母要改」。现在：

- `suggestions` 每条带 `scope`（`good` / `char`），页面「优先改」只渲染 `char`；
- 新增 `rowAdvice`：按条款 code 聚合行级问题，含 `lines / lineCount / criterion / detail`，页面单独渲染「整行章法提醒」，并提示格线纸上的行距与行首判据需对照原图人工复核。

### 口径影响

总分公式 `加权维度均值 × 0.6 + 最差维度 × 0.4` 未变，因此章法回升会显著抬高总分：英文 73 → 79（章法 61 → 70），中文 95 → 97（章法 93 → 96）。逐字母分不受行级条款影响，英文逐字母平均 84 → 86、单字规格约 91 的变化来自下伸字母不再误扣分。**分数用于定位练字重点，不等于考试卷面分**；词距、行距、行首三项在格线纸上仍有几何近似误差，报告与页面都保留人工复核提示。
